# PurgeKit v0.1 (Core) Implementation Plan

**Status:** implemented on branch `v0.1-core` (16 tasks). This file is the condensed record of the plan; the design is in `docs/superpowers/specs/2026-11-24-purgekit-design.md`.

**Goal:** A working, tested PurgeKit plugin that detects changes, purges 12 cache layers inside→outside, records history, warms the cache, and is controllable via REST, WP-CLI, a webhook and a minimal React dashboard.

**Architecture:** WordPress-free `Core` (Change, Queue, Planner, Executor, Flusher) behind small interfaces (`Store`, `Http`, `Lock`, `UrlExpander`, `Clock`); WP-specific code lives in adapters. Layers implement one `LayerInterface`. REST controllers call the same services as WP-CLI and the webhook; the React app only calls REST.

**Tech stack:** PHP 8.0+, Composer PSR-4, PHPUnit 9.6 + Brain Monkey, PHPCS (WordPress), PHPStan, `@wordpress/scripts`, `@wordpress/env`, GitHub Actions.

## Global constraints

- PHP 8.0+, WordPress 6.4+, GPL-2.0-or-later.
- Namespace `PurgeKit\`, slug/text domain/prefix `purgekit`, REST namespace `purgekit/v1`, hooks prefixed `purgekit_`.
- `src/Core/**` imports nothing from WordPress.
- Capability `manage_options`, filterable via `purgekit_capability`.
- Secrets: constant first, else sodium-encrypted option; never returned by any REST response.
- Layer tiers: object 10, plugin 20, host 30, proxy 40, CDN 50; purge runs ascending.
- Never `git add -A`; add explicit paths.

## Review focus

- Purge URLs on another host, with a fragment or empty: dropped (Planner).
- A layer that throws: recorded failed, remaining layers still run, run `partial` (Executor).
- Two flushes at once: second returns `locked` (Flusher).
- Autosaves, revisions, auto-drafts, non-public post types: no Change (Hooks).
- Cloudflare URL purge over 30 URLs: batches of 30.
- Webhook with missing/wrong/short key: 403, constant-time compare.
- Scheduled flush with empty queue and skip-if-unchanged: no layer called, history says `skipped`.

## Rulings made during implementation

- PHPCS doc-comment sniffs and snake_case method names are excluded (PSR-style code).
- PHPUnit pinned to ^9.6 because the WordPress test suite does not support PHPUnit 10+.
- `WpStore` wraps values as `array{v}` because `update_option( false )` is silently ignored for a missing option.
- `Flusher::flushAll()` drains the queue (a full purge covers pending changes).
- Webhook failures return an explicit 403 (WordPress would return 401 to anonymous callers).
- `@wordpress/private-apis` pinned via npm `overrides` so Jest resolves a single copy.
- Vendor function names in `Catalog` are best-known public APIs and still need verification against current vendor docs.
